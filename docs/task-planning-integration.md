# タスク統合・タイムライン

Private / Project 共通のタスク画面にボックス・タイムライン切り替え、日・週表示、5分刻みのドラッグ移動・伸縮、日付未定の引き出しを追加した。ボックスの時間設定は従来の `TimeBoxSchedule` を使う。開始時刻が属するボックスへ自動で移り、予定時間と見積時間は連動する。実行タイマーの `startAt` と予定の `plannedStartAt` / `plannedEndAt` は別の値。

ToDoタブ・メニューを撤去し、旧入口をタスクへ転送する。Privateの旧ToDoは固定の `todo-task:<旧ID>` に変換し、メモは標準のタスクメモとして取り込む。通知日時を予定時刻に変換しない。日付なしは `undated` 保存バケットに置く。元データは保持する。端末・アカウント・環境別のチェックポイント、本人専用のクラウド移行記録、固定ID、削除済みタスクの同期記録で再実行や部分失敗に対応する。旧形式の新規ToDoが後から同期された場合も取り込む。Projectでは同じレコードの `kind` を `task` に変えてID・既存メモを保持する。閲覧者の画面でも旧ToDoはタスクとして表示し、共有データの実際の変換はowner/memberが接続した際に行う。

## 通知と共有

- 通知は初期OFF。開始時刻、5/10/15/30/60分前、個別日時を指定できる。権限がなくてもタスクは保存できる。
- Projectの予定・見積・担当者・繰り返しは共有。通知は `users/<uid>/taskPreferences/reminders` の本人専用設定。ネイティブ通知IDは同期しない。
- 完了・削除・アーカイブ・通知OFFで予約を取り消す。予定変更では予約を差し替える。アカウントを切り替える際には、処理中の予約を無効化して取り消し完了を待つ。
- 通常の繰り返し通知はOSの継続する予約を利用する。未来の例外や未来の開始日など、OSの繰り返しでは表現できない場合は今後61日内の直近60件を予約し、起動・フォアグラウンド復帰・変更時に再計算する。この場合、長期間アプリを開かないと予約分以降の通知は更新されない。サーバーからの継続配信は実装範囲外。
- ドラッグ・伸縮はその回だけに適用する。編集画面でその回／全体を選べる。Privateの回ごとのメモも標準のメモ保存・検索へ接続する。Projectの回ごとのメモは共有する例外データに保存する。

## 展開の境界

本番へのデプロイ、クラウドデータの操作、Simulator・実機起動は行っていない。アプリでの移行は更新版を起動した際に実行される。

新しい項目・個人通知設定・Project閲覧者の編集制限を含む `firestore.rules` と、対応する `firestore.test.rules` を用意した。テスト環境で確認した後、アプリの配布前に対象環境のRules反映が必要。旧端末から予定情報を落とす更新はRulesで拒否するため、利用する端末は同じ更新版に揃える。移行記録は `users/<uid>/taskPreferences/todoMigration` にも保存する。これにより削除記録の保持期間終了後や新しい端末でも移行済みの旧ToDoを再作成しない。タスクと必要なメモの同期先が存在することを確認してからクラウド移行記録を確定する。オフライン中の移行記録は端末に保持し、再接続・次回起動で送信する。

## ユーザーによる手動確認

1. Private・Projectでボックス／タイムライン、日／週切り替えと再起動後の設定保存。
2. 各ボックスと日付未定の引き出しからの長押しドラッグ、画面端のスクロール、5分刻みの空き時間からの追加・移動・上下端の伸縮、キャンセル。
3. 別ボックス・別日への移動、時間重複、日またぎ、予定解除、見積時間の連動。
4. 作成・編集・メモ・タグ・担当者、キーボード表示中の操作、開始・一時停止・完了・アーカイブ・削除、時間未設定／繰り返しの回を含む一括移動・削除。
5. 通知の許可・拒否、開始前通知・個別通知、予定変更と完了後の取消、アプリを閉じた状態の受信、通知タップ。
6. 繰り返しのその回／全体編集と、完了済み・削除済みの回。旧ToDoのメモ・タグ・完了状態・繰り返し例外・通知の引継ぎ。
7. Projectの複数アカウントへの即時反映、閲覧者の共有編集禁止と個人通知の変更、Private側の担当タスクとの一致。
8. ログアウト・アカウント切り替え・本番／テスト環境切り替え後に他の範囲のタスクや通知が残らないこと。
