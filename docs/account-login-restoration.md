# 初回ログインとアカウント復元

- 初回インストールは言語選択後にApple／Googleログインとスキップを提示する。初回案内の完了は端末へ保存する。
- 同じプロバイダーの同じアカウントによるFirebase UIDを使用する。既存プロフィール・写真・Project・Commons・つながり・契約情報の取得方式と、アプリ全体のプロフィール設定必須ゲートは維持する。
- 新規インストールで初めてログインした際は同期設定をONにする。スキップ後のログインも対象。保存済みの明示的なOFFと既存インストールの設定は変更しない。
- Privateのクラウド復元は既存の同期権限に従う。権限の復元後に自動同期する。クラウドに未保存のデータを再インストールから復元することはできない。

## ローカルデータの所属

`@temis/account-workspace:v1` に既存保存先の所有UIDと現在のUIDを記録する。初回ログインでゲストデータをそのまま採用し、他のUIDには専用のAsyncStorageキーとSQLiteデータベースを使用する。アカウントを戻すと元の保存先を再利用する。ログアウトでは元のローカルデータの所属を維持するため、その後別アカウントへ自動追加されない。

既存のUID別同期メタデータがある場合はそのUIDを既存保存先の所有者として採用する。複数UIDの同期履歴がある旧インストールでは、所属を確定できない既存データを保存先に保持し、どのUIDにも自動送信しない。各アカウントは専用保存先でクラウドデータを復元する。

送信キュー・同期レコード・メモ・タスク・ToDo・タグは保存先ごとに分離する。認証・言語・同期ON/OFF・端末IDはインストール共通とする。アカウント切替はローカル書込みと実行中の同期の終了を待ち、復元結果の適用前にもUIDを確認する。

## 手動確認

1. 既存アカウントで必要なデータをクラウド同期し、別端末または再インストールしたアプリで同じApple／Googleアカウントを選ぶ。プロフィールの再入力なしで元の情報と同期対象データが戻ること。
2. 初回案内をスキップし、Privateデータを作成してからログインする。ゲストデータと元のクラウドデータが重複せず統合されること。
3. 新規アカウントでは表示名とユーザーネームの設定完了までアプリ全体を利用できないこと。
4. 明示的な同期OFFを維持すること。同期権限のないアカウントは端末内データを保持し、権限取得後に同期すること。
5. A→ログアウト→B→Aの切替で、AのPrivateデータがBへ表示・送信されず、Aへ戻した際に保持されていること。
6. ログインキャンセル、通信失敗と再試行、アプリ完全終了後のApple／Google認証維持を確認すること。

AppleとGoogleを互いに追加して同一UIDへ連携する機能は含まない。今回の変更にバックエンドのデプロイは不要。
