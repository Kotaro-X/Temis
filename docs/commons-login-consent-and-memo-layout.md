# Commons投稿・初回ログイン同意・メモ表示の修正（2.0.0 / 119）

## 変更

- 更新後の初回ログイン／既存セッション復元時に、サーバーのUID別同意記録を確認する。未確認・説明バージョンが古い場合は通常画面の前にOpenAI送信の共通説明画面を表示する。
- 「同意する」「同意しない」の双方をサーバーに保存する。現行バージョンの回答済みアカウントには以降表示せず、Commons投稿時も確認画面を出さない。拒否・撤回後の変更は設定から行う。
- 同意の読み取り失敗時は再試行、またはAIを利用せず通常編集へ進める。同意保存に失敗した場合は説明画面に留まり、保存成功として扱わない。アカウント切替後の古い応答を反映しない。
- Commons投稿・明示的な再試行がバックグラウンドの処理と重なった場合、処理待ちの後に新しいキューを処理する。アカウントをまたいで待機結果を共有しない。公開Callableのクライアント待機時間をサーバーの120秒より長い150秒に揃える。
- PrivateとProjectで同じMemoDetailLayout／MemoEditorFields／MemoBodyEditorModalを使う。共通詳細にSafeAreaProviderを設け、ステータスバーにヘッダーが重なる問題を修正。縦スクロール・本文の最小高さ・Wikiチップの最大幅を設定し、長い本文やリンク、低い画面でも操作へ到達できるようにする。
- 本文編集とメモからの投稿フォームは詳細画面内の全画面表示に統一し、背後の入力・アクセシビリティ操作を停止する。本文に「編集」ボタンも追加。本文エディターの表示領域はキーボード位置から独立して計算し、詳細画面はiOS標準のスクロール領域調整を使用する。
- ExpoのbuildNumberとiOSのInfo.plist／Debug・ReleaseのCURRENT_PROJECT_VERSIONは119。バージョンは2.0.0を維持する。EAS productionはremote採番＋autoIncrementのため、現行118を採番基準に設定して次回119とする。

## 原因確認・反映範囲

2026-10-10の本番照会で公開・同意状態だけを集計したところ、aiConsentsは0件、安全判定済みの投稿は0件だった。投稿画面の上から別モーダルの同意画面を呼ぶ経路があり、今回の初回ログイン画面によって投稿モーダル内の同意取得を不要にした。

前回反映した5 Functions・投稿関連Rulesを使用する。今回のコード変更はアプリ側のみで、追加のFunctions／Rulesデプロイや既存投稿の移行は不要。実アカウントの同意は代理付与していない。

## 手動確認

1. 更新後のログインで説明・同意する／同意しないの両方を確認する。拒否してもPrivateの編集・キーワード検索を利用できること。
2. 同意したアカウントでCommonsに2回投稿し、2回目に同意確認が表示されないこと。再ログインしても確認が繰り返されないこと。
3. 設定から撤回・再同意を行い、拒否中は投稿できず、再同意だけで過去の投稿が再公開されないこと。
4. Private／Projectで長文・長いタイトル・多数のWikiリンクを開き、縦スクロール、本文編集、キーボード表示時の完了・戻る操作を確認する。
5. ビルド119のTestFlight／実機配布は別工程。今回のシミュレーターDebugビルドは配布完了を意味しない。
